# Форматы подписок

[← README](../README.md) · [Диагностика](troubleshooting.md)

Happy автоматически определяет контейнер подписки. Поддержка формата не добавляет новые VPN-ядра: подключение доступно для VLESS, VMess, Trojan и Shadowsocks. Hysteria2 и AmneziaWG остаются отдельными задачами.

| Контейнер | Поведение Happy |
|---|---|
| Открытый список ссылок | Одна ссылка на строку; комментарии и пустые строки допускаются |
| Base64 / Base64url | С паддингом или без него; после декодирования определяется внутренний формат |
| JSON-объект Xray | Одна конфигурация становится одним сервером |
| JSON-массив Xray | Каждый объект становится отдельным сервером; дубликаты схлопываются |
| Смешанный текст со строками routing/autorouting и метаданными | Ссылки импортируются, метаданные извлекаются; служебные строки не считаются узлами |
| JSON-контейнер `type: "amneziawg"` | Распознается и пропускается; остальные Xray-конфигурации массива импортируются |
| WireGuard / AmneziaWG `.conf`, включая Base64 | Распознается; возвращается явная ошибка о неподдерживаемом протоколе |

Список контейнеров сверен с [документацией INCY](https://docs.incy.cc/subscription-format/). Это совместимость форматов импорта с текущими протоколами Happy, а не полная совместимость с функциями INCY. Импорт routing/autorouting-профилей и автоматическое скачивание их URL не выполняются: такие строки не меняют настройки шлюза.

## JSON Xray

Пример структуры без настоящих учетных данных:

```json
[
  {
    "remarks": "Первый сервер",
    "inbounds": [],
    "outbounds": [
      {
        "tag": "proxy",
        "protocol": "vless",
        "settings": {
          "vnext": [
            {
              "address": "vpn.example.net",
              "port": 443,
              "users": [
                { "id": "123e4567-e89b-12d3-a456-426614174000", "encryption": "none" }
              ]
            }
          ]
        },
        "streamSettings": {
          "network": "tcp",
          "security": "tls",
          "tlsSettings": { "serverName": "vpn.example.net" }
        }
      }
    ]
  }
]
```

Поддерживаются одиночный объект и массив объектов, в том числе в Base64-обертке. Имя берется из `remarks`, затем из тега первого прокси-выхода или его адреса. В панели такая запись обозначается как `XRAY`; адрес и проверка TCP-порта относятся к первому прокси-выходу, а не ко всему балансировщику.

Happy сохраняет совместимые `outbounds`, `routing`, `dns`, `policy`, `observatory` и `burstObservatory`. Балансировщики и связи выходов через `sockopt.dialerProxy` сохраняются. Теги изолируются от внутренних тегов шлюза, а ссылки на клиентские SOCKS/HTTP-входы переводятся на собственные входы Happy. Проверки Observatory не являются проверками WireGuard-канала устройства.

Собственные правила блокировки Happy и его внутреннего DNS стоят перед правилами провайдера. Далее применяются правила полной конфигурации, включая ее явные direct-правила; при отсутствии совпадения используется первый выход конфигурации. При отключении выхода провайдерская конфигурация не включается в работающий Xray вообще.

Входы, `env`, лог-файлы, API и прочие настройки процессов провайдера не переносятся. Приватные ключи/сертификаты из файлов и отключение TLS-проверки не принимаются. GeoIP/GeoSite включены в поставку из закрепленного архива Xray. Внешние пользовательские Geo-файлы автоматически не скачиваются; отсутствующая база или несовместимая настройка будет обнаружена проверкой Xray при применении.

Конфигурация с протоколом, который Happy пока не поддерживает, пропускается целиком: удаление только одного выхода могло бы нарушить связи и балансировку. Служебные `freedom`, `blackhole` и `dns` внутри совместимой конфигурации сохраняются, но сами по себе не создают сервер в списке. Поврежденная поддерживаемая конфигурация останавливает обновление с сохранением последней корректной версии подписки.

## Ограничения

- Размер ответа — до 4 МиБ, число уникальных серверов или JSON-конфигураций — до 2000; у одной JSON-конфигурации допускается до 2000 выходов.
- Подписка, в которой после пропуска неподдерживаемых записей не осталось серверов, считается ошибочной.
- HTTP-заголовки метаданных имеют приоритет над строками `#ключ: значение` в теле.
- Полные конфигурации, ключи и URL подписок не выдаются в публичном состоянии панели и не печатаются в диагностических сообщениях.

Семантика полноценных конфигураций описана в [справочнике INCY](https://docs.incy.cc/full-xray-config/); Happy адаптирует ее к собственным входам и ограничениям шлюза.
