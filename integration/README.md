# WireGuard end-to-end test

Тест использует настоящий закреплённый Xray и wireguard-go/netstack в userspace. Root, `/dev/net/tun`, внешняя сеть и подписка провайдера во время теста не нужны. Для загрузки зависимостей и Xray сеть нужна только на этапе подготовки.

```sh
sh scripts/fetch-xray.sh amd64 ./bin # Linux arm64: arm64; macOS arm64: darwin-arm64
cd integration
HAPPY_TEST_XRAY=$PWD/../bin/xray go test -mod=mod -race -v -timeout 120s ./...
```

Поднимаются локальный VLESS-провайдер и TCP/UDP цели. Проверяются отсутствие выхода без подписки, TCP и DNS-подобный UDP через WireGuard → VLESS, блокировка LAN/IPv6, отзыв старых ключей и блокировка при исчезновении выбранного узла. Публичные адреса внутри туннеля перенаправляются тестовым провайдером на локальные цели; реальные внешние запросы не выполняются.

Без `HAPPY_TEST_XRAY` тест пропускается. В окружении, запрещающем bind TCP/UDP, этот тест выполнить нельзя. CI запускает его на Linux.

Диагностика разделяет выбранный VLESS-выход через локальный HTTP-прокси Xray, свежий WireGuard-handshake, TCP через туннель и восстановление существующей сессии после перезапуска Xray. При сбое выводятся только счётчики WireGuard (время handshake, tx/rx) и количество обращений к локальной HTTP-цели; полный UAPI с приватными ключами не выводится. Точный ответ локальной цели проверяется с общим пределом ожидания 30 секунд. Готовность VLESS-провайдера проверяется по TCP. Адрес `1.1.1.1` служит целью внутри туннеля; тестовый провайдер перенаправляет его на локальный сервер.

Freedom в закреплённом Xray по умолчанию блокирует приватные назначения для VLESS, включая адрес после `redirect`. Поэтому тестовый провайдер получает `finalRules` с `allow` для точных loopback IP, портов и протоколов своих TCP/UDP-целей. DNS-прокси Happy использует отдельное такое разрешение исключительно для своего внутреннего loopback-порта, доступного через правило `10.77.0.1:53`. Защита остальных LAN-адресов сохраняется. См. [Freedom finalRules](https://xtls.github.io/en/config/outbounds/freedom.html).


`TestWireGuardDNSProxyThroughProvider` проверяет настоящий DNS на виртуальном адресе `10.77.0.1:53`: UDP/TCP от WireGuard-клиента, UDP/TCP к основному DNS через VLESS, внешний DNS-порт, блокировку вместе с кешем при отключении выхода, резервный сервер через хост и возврат на основной путь. Для проверок после выключения/включения выхода создаётся свежая WireGuard-сессия, чтобы тестировать DNS независимо от восстановления старой сессии после перезапуска ядра.
